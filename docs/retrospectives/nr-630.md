## wasm-pack test failed locally with "http status: 404" from ChromeDriver, an eighth time

**What happened.** The `wasm-pack test --headless --chrome` leg failed before any test ran (`driver status: signal: 9 (SIGKILL)`, `Error: http status: 404`). Setting `CHROMEDRIVER=<path>` did nothing, because wasm-pack exports its own cached path over it.
**Why.** As nr-09s recorded: wasm-pack's cached ChromeDriver is 154.0.8037.57 and the installed Chrome is 153.0.8010.53. New this time: `./scripts/gate-full.sh` passes this leg unchanged when a ChromeDriver 153 directory is put first on `PATH` (`PATH=<dir>:$PATH ./scripts/gate-full.sh`), because wasm-pack uses a `chromedriver` found on `PATH` before its cache. That lets the whole gate run in one go, rather than running this leg by hand with `--chromedriver`.
**Cost.** About fifteen minutes, including two failed runs that used the environment variable.
**Prevent by.** Updating Chrome, or deleting `~/Library/Caches/.wasm-pack/chromedriver-*`, on the fleet machine. Until then, `produce-bead` *Building* (or `scripts/gate-full.sh`) could look for a Chrome/ChromeDriver major-version mismatch and print the `PATH` workaround.
**Seen before.** nr-09s, nr-6e9, nr-nr7, nr-aph, nr-273, nr-ps1, nr-qoi.

## The gate's Python legs failed with 29 import errors in a fresh worktree

**What happened.** `./scripts/gate-full.sh` failed at `py -m unittest discover -s scripts …` with `FAILED (errors=29)`: `No module named 'requests'` / `'rich'` / `'bs4'` / `'tqdm'`, and `module 'scripts.metadata_scraper' has no attribute 'main'`. The prepared worktree has no `.venv`, so `py()` falls back to the system `python3`. The main checkout's `.venv` does not help either: it lacks those packages and `mypy`.
**Why.** `scripts/prepare-worktree` / the project's `install` does not create the Python environment that CI installs from `scripts/pyproject.toml` (`--group …:test --group …:dev`).
**Cost.** About ten minutes, plus a scratch venv. With `pip install --group scripts/pyproject.toml:test --group scripts/pyproject.toml:dev`, all four Python legs passed (unittest 452 OK, ruff check, ruff format, mypy).
**Prevent by.** Adding a `.venv` build from those two dependency groups to the `install` line in `.cerebro/project.conf`, so every prepared worktree has one, or having `gate-full.sh` say which interpreter it fell back to.
**Seen before.** None found.

## The agreed Grey shades contradicted "today's shades, unchanged"

**What happened.** The acceptance listed Grey as #FFFFFF #ADADAD #525252 #000000 and also called it "today's shades, unchanged". The code draws #AAAAAA/#555555 (`src/gb/ppu/rendering.rs` `DMG_GREY`). The navigator was asked during design and chose today's values.
**Why.** Not established. The mockup's hex was probably written from memory rather than from the code.
**Cost.** One question to the navigator during design. Had the hex been built as written, every DMG golden frame would have changed.
**Prevent by.** `agree-experience`: whenever an agreed colour or value is described as "unchanged" or "as today", the UX session copies it from the code (and names the file) instead of typing it into the mockup.
**Seen before.** None found.
