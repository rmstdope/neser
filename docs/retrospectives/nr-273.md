## wasm-pack test failed locally with "http status: 404" from ChromeDriver, a fifth time

**What happened.** `./scripts/gate-full.sh` failed its wasm leg: `driver status: signal: 9 (SIGKILL)` then `Error: http status: 404`. A rerun gave the same result. Setting `CHROMEDRIVER=<a 153 driver>` in the environment changed nothing, because wasm-pack exported its own cached path over it (visible in the `full command:` line of the error).
**Why.** The same cause nr-09s recorded: wasm-pack's cached ChromeDriver is 154.0.8037.57 and the installed Chrome is 153.0.8010.53. New here: wasm-pack overrides the `CHROMEDRIVER` environment variable, so only its `--chromedriver <path>` flag works.
**Cost.** About twenty-five minutes and three wasm builds. The leg passed (94 tests) with ChromeDriver 153.0.8010.53 from Chrome for Testing, passed through `--chromedriver`.
**Prevent by.** The prevention nr-09s names: `scripts/gate-full.sh` passes `--chromedriver` pointing at a driver that matches the installed Chrome, or fails with a clear version-mismatch message. Setting `CHROMEDRIVER` is not enough, because wasm-pack overrides it.
**Seen before.** nr-09s, nr-qoi, nr-6e9, nr-nr7.

## The Python gate legs fail in a fresh worktree: no `.venv`

**What happened.** The worktree has no `.venv`, so `py()` in `scripts/gate-full.sh` fell back to system `python3`: 29 unittest errors and no mypy. The main checkout's `.venv` had no mypy either.
**Why.** `install` in `.cerebro/project.conf` runs only `npm ci`, so it never creates a venv.
**Cost.** About five minutes to build a scratchpad venv with `pip install --group scripts/pyproject.toml:test --group scripts/pyproject.toml:dev`. Then: 452 tests OK, and ruff and mypy clean.
**Prevent by.** The prevention nr-qoi names: extend `install_shell` in `.cerebro/project.conf` to create `.venv` with both dependency groups, or make `py()` fail with a clear message.
**Seen before.** nr-qoi, nr-6e9, nr-nr7.

## `build-workload --classify` refused to classify the diff

**What happened.** The produce-bead *Building* step printed `build-workload: no rust_paths in .cerebro/project.conf - cannot classify safely.` instead of a workload.
**Why.** `.cerebro/project.conf` declares no `rust_paths`.
**Cost.** A minute. The plan already declared `rust`, so I ran `disk-preflight --workload rust` myself.
**Prevent by.** Declare `rust_paths` (for example `src/ Cargo.toml Cargo.lock build.rs`) in `.cerebro/project.conf`.
**Seen before.** none found.
