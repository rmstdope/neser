Steel Glow, round 2 — desktop

The whole web app in Steel Glow, with the UX changes I suggest, one screen per state. Items marked new are changes in how things work, not only in how they look; each one is a separate yes/no.

1Start screen: the library new

Today the start screen is a scrolling message on an empty canvas, with a file picker and a dropdown in the sidebar. Suggested: the start screen is the place to pick a game. A big drop target (you can drop anywhere on the page), Continue playing with the last games you ran (kept in this browser, like the SNES firmware), and the bundled test ROMs as a searchable list with system filters. Picking a game starts it at once, so the separate Start step goes away. The sine scroller carries the release news, as it does today.

2Playing new

Today the controls are split: zoom, filter and mute along the top, Start/Pause/Reset/Stop/Save/Load in the sidebar. Suggested: the sidebar goes and the game gets the room. Every in-game control sits in one control bar under the picture, the way video players do it: play and reset on the left, save states in the middle, picture and sound on the right. The game's name and system move to the top bar. Hovering a control shows its keyboard shortcut. Stop becomes Eject, which returns you to the library. Mute becomes a volume control.

3Filter, palette and reset open as short lists new

Today Filter, Palette and the GB colour button cycle on every press, so you only learn the options by pressing through them. Suggested: each opens a short list showing every choice with the current one ticked; the F4 and F8 keys still cycle. Reset gets a list too, so the hard reset you can only reach today with Shift+Ctrl+R is visible. Only the choices for the running system appear.

4Paused

The picture dims behind a play button you can click. The bar's Pause turns into a lit Resume. Picking another game from the top bar's Library keeps this one paused underneath until you choose.

5Saving and loading a state new

Today Save State and Load State are two buttons with no hint of what is saved. Suggested: after a save a short message confirms it, and hovering Load shows a picture of the saved moment and when it was taken. Still one save per game, as today. On a Game Boy Advance game, where states aren't supported yet, both are greyed with the reason on hover.

7Debugger docked beside the game new

Today the debugger is drawn over the picture, so you can't see the game and its state at once. Suggested: F5 (or the bug button, shown once it is switched on under Developer) docks it as a panel to the right and the picture shrinks to make room, the way desktop emulators show it. Its panes keep today's contents (registers, disassembly, memory, watches, trace, sprites and the PPU view) and the stepping keys stay F10 and F11.

8Keys and controller help new

Today H shows a grey text box over the corner of the picture. Suggested: a proper panel with key caps, shortcuts on the left and the running system's controller on the right, drawn as a pad with each button's key beside it. Tabs show the other systems' keys. A connected gamepad replaces the keys with "Gamepad". H or Esc closes it.

9When something goes wrong

Today errors are a line of small red text under the picture. Suggested: a file that can't be opened shows a message on the library, where you are, with the way forward as a button. An error while a game runs stops the picture, says so on it, and offers Reset and Back to library. Short messages (firmware stored, controller connected) stay as brief notes at the top.
