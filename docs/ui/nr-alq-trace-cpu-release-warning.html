CPU trace in a release build — help line and NES-only warning

Same help line as A. The warning appears only when the game being run is an NES game. Super Nintendo, Game Boy and Game Boy Color runs, whose instruction lines do print in a release build, get no warning.

neser --help (same text in every build)

$ neser --help
...
Trace and Debugging:
  --trace             Enable CPU trace output (NES instructions only in debug builds)
  --trace-cpu         Enable CPU trace output (NES instructions only in debug builds)
  ...

Release build, NES game, headless

$ target/release/neser --headless --trace-cpu --output out.png game.nes
warning: --trace-cpu: this release build prints no NES instruction lines; build without --release for them
[CPU] NMI ...

Release build, Super Nintendo game — no warning

$ target/release/neser --headless --trace-cpu=2 --output out.png game.sfc
00:8000 SEI ...
  [read] 00:8000 ...

Release build, windowed, no game on the command line — then an NES game opened from the menu

$ target/release/neser --trace
(window opens; nothing printed yet)
(game.nes chosen from the menu)
warning: --trace: this release build prints no NES instruction lines; build without --release for them
[CPU] NMI ...

Started without a game: the warning appears once, as the first NES game of the run starts, before any trace line.

Debug build, NES game — no warning

$ target/debug/neser --headless --trace-cpu --output out.png game.nes
C000  78        SEI ...
[CPU] NMI ...
