SNES DSP-1 firmware — agreed

How a player supplies the DSP-1 firmware (Super Mario Kart, Pilotwings) and what they see without it, on the desktop and in the browser.

Option A — one folder for all chip firmware

The player drops the chip's firmware file, under its usual name, into one folder. Neser looks there whenever a game needs one. The same folder will later hold the DSP-2, DSP-3, DSP-4, ST010 and ST011 firmware too, with no new setting each time. This is how most SNES emulators work (a "system" or "firmware" folder with fixed file names).

Where the files go by default

~/.neser/firmware/dsp1b.rom     ← DSP-1B (Super Mario Kart, Pilotwings, and most DSP-1 games)
~/.neser/firmware/dsp1.rom      ← the original DSP-1 (optional; used when a game wants that exact chip)

The settings file (new block in the SNES section)

# Folder holding SNES coprocessor firmware files.
# Some SNES cartridges carry a math chip (DSP-1) whose program is stored in
# the chip itself. Game dumps do not contain it, and NESER cannot include it,
# so these games need a firmware file you supply, placed in this folder under
# its usual name:
#   dsp1b.rom  - DSP-1B (Super Mario Kart, Pilotwings, and most DSP-1 games)
#   dsp1.rom   - original DSP-1 (used instead of dsp1b.rom when present and
#                the game was built for the original chip)
# Each file must be exactly 8192 bytes.
# Default: ~/.neser/firmware
#snes-firmware-dir=/absolute/path/to/firmware

Command-line help

--snes-firmware-dir  Folder holding SNES coprocessor firmware such as dsp1b.rom (default: ~/.neser/firmware)

Cost: the player must use the exact file name; a file called “Nintendo DSP-1B (1993).bin” is not found until renamed.

Option A — the game does not start; the reason is shown where the player is

Neser checks for the firmware before starting. Without it, no game window opens. Other emulators (Mesen, RetroArch) do the same. Today a game that fails to start from the game browser only leaves a line in the terminal, so the browser gains a message strip at the top.

Started from the command line

$ neser "Super Mario Kart (USA).sfc"
Error: Super Mario Kart (USA).sfc needs the SNES DSP-1 firmware, which was not found.
Put dsp1b.rom in /Users/henrik/.neser/firmware, or point --snes-firmware-dir at the folder holding it.

Cost: a new message strip in the game browser. (Words assume Option A for the folder; they follow whichever you choose.)

Option A — the strip explains every game that fails to start

Today any game that fails to start from the game browser just sends the player back to the browser without saying why. With this option, the new strip shows the reason for every failure, not just the missing firmware. The first line is always “<game> can’t start.”. The second line is the reason Neser already gives (that wording is not changed here).

Option A — the strip stays until another game starts

After the failure the browser comes back with the same game still selected. The strip sits above the games and never takes a key or button. The player keeps browsing with the keyboard or controller as usual, so Esc, the arrows and Enter behave exactly as before. The strip goes away when any game starts. A mouse user can also click ✕. If the player tries the same game again and it fails again, the strip is replaced with the new reason.

Option B — the browser version asks for the firmware file once

When a DSP-1 game is opened and no firmware is stored, a small dialog asks for it. The file is kept in this browser, so the next DSP-1 game starts straight away. Browser-based emulators commonly ask for a BIOS this way.

Open ROM…Super Mario Kart (USA).sfc
This game needs the DSP-1 firmware

Choose your dsp1b.rom file (8 KB). It stays in this browser, so you only do this once.

CancelChoose file…

After choosing a wrong file

Open ROM…Super Mario Kart (USA).sfc
That isn’t a DSP-1 firmware file

“mario.zip” is 1.2 MB; the firmware is exactly 8 KB.

CancelChoose file…

Cost: a new dialog and stored file in the browser version — noticeably more to build than A.

Option A — the sidebar shows the stored firmware, with Replace and Forget

Once a firmware file has been stored, a small “SNES firmware” block appears under the ROM choosers. Before that, nothing is shown there, and the player only ever meets the question through the dialog. “Replace…” opens the same file chooser as the dialog. “Forget” removes the stored file at once, without asking to confirm, and the block disappears. The next DSP-1 game then asks again.

Every word a player reads — please check

These are the words exactly as they will ship, following your choices: one firmware folder, refusing to start, and asking in the browser. <game> is the game’s file name without its ending, e.g. “Super Mario Kart (USA)”. <folder> is the full firmware folder path on that computer.

Desktop — game browser strip, firmware missing

<game> can’t start: it needs the DSP-1 firmware.
Put dsp1b.rom in <folder> and try again.

Desktop — game browser strip, firmware file is the wrong size

<game> can’t start: the DSP-1 firmware isn’t valid.
<folder>/dsp1b.rom is 12,288 bytes; it must be exactly 8,192 bytes.

Command line — firmware missing (Neser then exits)

Error: <game> needs the SNES DSP-1 firmware, which was not found.
Put dsp1b.rom in <folder>, or point --snes-firmware-dir at the folder holding it.

Command line — firmware file is the wrong size

Error: <folder>/dsp1b.rom is not valid SNES DSP-1 firmware: it is 12,288 bytes; it must be exactly 8,192 bytes.
